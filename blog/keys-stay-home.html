Your agents shouldn't hold your keys

An agent that can read a key can leak it. So in KALYPSO, agents never get one. Here is how the keys stay home, and what changed this week.

The quickest way to give an agent a model is to paste an API key into its environment. It's also the quickest way to lose that key: anything the agent can read, it can print, log, commit or send somewhere. KALYPSO starts from the other end. Agents never hold your real keys.

A stand-in key, swapped at the gateway

Each agent gets a kx_ key. It only works against the KALYPSO gateway running on your machine, and you can revoke it at any time. When the agent calls a model, the gateway checks the call, meters it against your budget, and only then adds your real provider key on the way out. The real key lives encrypted in the Vault and never enters a sandbox.

Secrets an agent needs arrive as files

Some work does need a secret, like a GitHub token to open a pull request. You give it to the agents that need it, from the Vault or from the agent's page, and it appears as a file in /run/kalypso/secrets. It never goes into a prompt.

New this week: the gateway scrubs them too

A file the agent can read is still something the agent can quote. If a delivered secret ends up in a model request, say because the agent pasted a config file into its context, the gateway now replaces it before the request leaves your machine. If it can't check a request, it doesn't send it.

  • Real model keys: in the Vault, added at the gateway, never in a sandbox.
  • Delivered secrets: files in /run/kalypso/secrets, given per agent.
  • Model requests: checked and scrubbed of delivered secrets before they leave.

The details are in the pull request, and the whole design is in the architecture notes.
